THE PRODUCT THAT STARTED IT

A File Manager was the beginning.
The security challenge became the mission.

The journey did not begin with a security framework. It began with a practical Windows File Manager and a question: what does dependable file handling require beneath the user interface?

Understand the architecture View real progress
THE ORIGIN

From everyday workflows to systems research.

The user-facing application and the deeper security library are related, but they are not the same product.

01

Build a useful File Manager

The initial objective was a desktop file experience focused on practical operations and usability, developed as an independent application.

02

Understand the security boundary

File operations involve more than paths and buttons: volume identity, access rights, native handles, concurrent processes, revocation, and partial failure all matter.

03

Create AegisFS as a separate foundation

Instead of forcing every concern into the File Manager, AegisFS became its own Rust-based, Windows-first filesystem security research project.

04

Rethink cross-process authority

Repeated mutex, lock-file, and crash-recovery design limitations motivated a new direction: a single broker-controlled authority, tested first in isolation.

TWO DEVELOPMENT TRACKS

Independent today.
Potentially integrated later.

The File Manager follows a separate release path using its current interim security approach. AegisFS is not yet part of that shipping product; integration is a future goal, conditional on security validation.

That separation avoids treating unfinished research as a dependency for useful software delivery.
